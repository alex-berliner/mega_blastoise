UI Concept Mockups

Mega Blastoise: one screen, two players

Flow mockups for the single-screen redesign: a 2.8" IPS 240x320 panel laid flat between the seats, split into two 240x160 halves. The far player's half is rendered rotated 180 degrees, so both players always read upright. Open information by design: no hidden choice. Each seat gets a D-pad plus A and B.

2.8" IPS ST7789, 240x320split portrait, both phasesD-pad + A/B per seatrotationally symmetric seatslandscape only for attract

00Hardware frame

Controls are placed with rotational symmetry, not mirrored. Each seat gets D-pad on the left, A/B on the right, in its own reading orientation (the far cluster looks upside down from here, which is correct). Notes:
  • D-pad moves the cursor, A confirms, B backs out: every state now has an explicit back path, and nothing commits on a stray tap.
  • Panel must be IPS; a TN panel shows inverted contrast to one of the two seats.
  • The WS2812 strips are dropped; HP lives on-screen. Optionally keep one status LED per seat.

01Attract, landscape for bystanders

The only landscape state. Bystanders view the table from the side, so the demo battle plays oriented toward them. Any button enters the lobby.

02Lobby and ready-up

First button press flips the screen to split mode. Each half readies independently; a countdown starts when both are ready.

03Move choice, the core screen

Foe HUD on top of every choice half: species, level, HP, status. Cursor on a 2x2 move grid; the info bar always describes the highlighted move, so inspect costs nothing and needs no hold gesture.

04Locked in

05Turn playback, mirrored per half

No 90-degree flip. Both halves play the same event simultaneously, each from its own seat's perspective: your mon in back view, the foe in front view, exactly like the two-OLED build but with color, HP boxes, and both mons on one canvas.

What this buys, against the audit: foe visibility at all times (HUD + front sprites + open bench scouting), explicit confirm/back everywhere, opponent-locked signal, per-event pacing floor with intentional fast-forward, no rematch deadtime, one panel so no cross-screen skew, and the LED power problem disappears with the strips. What it costs: hidden choice is gone (the locked state hides only the move name, and only until playback), and the corner-button = corner-move mapping is replaced by cursor + confirm, which is more familiar but less magic. Total inputs: 12 switches vs 14 today.
