# Coverage grid: check classes by subsystem (REF-A, hardware/ref_design)

Generated by `python3 hardware/vv/tools/grid.py` from verification.csv (each check's `classes` and `subsystems`) and grid_reasons.csv. Do not edit by hand: change those files and re-run it. `check_trace.py --gate order` fails (R9) while any cell of classes 1-15 is GAP or planned. A cell of classes 1-14 is cleared only by a built check that runs before the boards exist: an ORDER check or an analysis (A); a later bench test, inspection or demonstration measures it but does not clear it. Class 15 is cleared only by a paper estimate that has run: an analysis with a PASS or FAIL. Classes 16-18 belong to EVT, DVT and PVT and are shown, not gated by the order; 19 and 20 are whole-register classes, listed below. Only checks of board ref_design or both count; CUT and RETIRED checks never do.

A cell reads: COVERED, worst <status> (FAIL, NOT_BUILT, NOT_RUN, PASS) among the checks that can clear it (classes 16-18: among all its checks) and, when no clearing check is an ORDER check, the earliest phase, then the later checks that measure it but cannot clear it; planned (the checks that could clear it once built or run, then the ones that measure it but cannot clear it: a GAP for the order gate); GAP; NOT_NEEDED (grid_reasons.csv says why).
